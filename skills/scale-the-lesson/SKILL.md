# Scale the lesson

Capture an observed finding while its evidence is available. Apply a change immediately only when it is reversible and within the current task's authority. Capture now and defer the mutation when that boundary is unclear.

## Choose the smallest useful destination

Ask whether the finding changes a future decision, cost, safety condition or repeated failure. If not, its receipt is enough.

A local default changes only the current worker's reversible practice. It must not change another worker's obligations, shared routing, budget semantics or security controls. Those are proposals for the relevant owner.

A proposed shared change carries four fields: lesson, evidence, proposed change and cost or tradeoff. Keep it pending until the owner rules. Being useful does not grant authority to apply it.

Use an existing receipt, task note or learning inbox rather than silently creating a new registry. During an incident, one line with the observation and evidence pointer is sufficient until the next natural boundary.

## Close the capture loop

At that boundary, route the finding to a receipt, an authorized local default, an owner proposal, an existing related lesson, or a documented discard. Capturing it is not applying it.

For an unresolved proposal, record an owner and revisit date. At review, adopt, defer with a new date, refresh the evidence or discard. Discarding an unsupported proposal does not prove the original concern false.

Escalate only a repeated failure, a consequential one-off, a proposed shared rule or a material change in execution behavior. Other details remain in receipts. Keep learning work proportional to recurrence and consequence, so recording lessons does not consume the work it was meant to improve.
